# Сообщение об уязвимости

Не публикуйте в открытых issues пароли, токены, персональные данные или подробности, которые помогают атаковать действующую установку.

Если на вкладке **Security** доступна кнопка **Report a vulnerability**, отправьте сообщение через GitHub Private Vulnerability Reporting. Если кнопки нет, не размещайте технические детали публично; свяжитесь с владельцем репозитория по закрытому каналу.

Для владельца репозитория: включите **Settings → Code security and analysis → Private vulnerability reporting**, чтобы пользователи могли сообщать об уязвимостях приватно.

Публичный Supabase anon key и клиентские API-ключи не являются секретами. Доступ к данным Supabase должен ограничиваться RLS; service-role keys и токены серверных интеграций нельзя публиковать.
