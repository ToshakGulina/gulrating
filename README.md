## Возможности

- Общая лента оценок друзей с комментариями, фильтрами и сортировкой.
- Поиск фильмов и сериалов через TMDb; карточки с постером, годом, описанием и рейтингами.
- Оценки с точностью до десятых, список «Хочу посмотреть» и статистика профиля.
- Вход по паролю; администратор одобряет новых участников.
- Синхронизация истории просмотров и настроек между устройствами одного аккаунта — после установки миграции Supabase, см. ниже.
- PWA для браузера и Android APK без Google Play.
- Локальная оболочка и сохранённые данные доступны офлайн после первого входа/кэширования. Поиск, серверные данные и видео офлайн недоступны.

## Для пользователей

### Веб-приложение

Откройте [gulrating.pages.dev](https://gulrating.pages.dev/), создайте аккаунт с паролем и дождитесь одобрения администратора. Первый пользователь нового проекта Supabase автоматически становится администратором. На телефоне веб-приложение можно установить на главный экран через меню браузера. Установленная PWA получает офлайн-оболочку после первого успешного открытия с сетью.

### Android APK

Скачайте **последний APK** со страницы [GitHub Releases](https://github.com/ToshakGulina/gulrating/releases/latest), откройте файл на телефоне и разрешите установку из этого источника, если Android спросит. Google Play не используется. Начиная с выпуска v1.0.21 используется новый ключ подписи: APK нельзя установить поверх версии до v1.0.21. Перед установкой новой версии удалите старый APK и проверьте, что важные данные синхронизированы; локальные данные при удалении приложения могут пропасть.

APK содержит копию оболочки сайта для запуска при недоступности `pages.dev`. Первый вход в аккаунт и обновление общих данных требуют интернета. Для продолжения просмотра также нужна сеть.

### Синхронизация истории и настроек

Для владельца/администратора проекта это одноразовая настройка базы данных:

1. В Supabase откройте **SQL Editor → New query**.
2. Скопируйте содержимое [`supabase-user-sync.sql`](supabase-user-sync.sql) и нажмите **Run**.
3. Войдите в ГульРейтинг под одним и тем же аккаунтом на каждом устройстве. Синхронизация выполнится при наличии соединения с Supabase.

Таблица защищена RLS: аккаунт может читать и изменять только собственную запись. Оценки и списки компании хранятся отдельно в основных таблицах Supabase.

Оценки отдельных серий требуют таблицы `episode_ratings`: для уже созданного проекта один раз повторно выполните актуальный [`supabase-schema.sql`](supabase-schema.sql) в SQL Editor. Скрипт идемпотентный и не удаляет существующие оценки.

## Развёртывание собственной копии

Приложение — статический сайт без обязательной команды сборки. Для полной функциональности используются Supabase и Cloudflare Pages.

1. Создайте проект Supabase и выполните [`supabase-schema.sql`](supabase-schema.sql). Если нужна синхронизация настроек и истории — также выполните [`supabase-user-sync.sql`](supabase-user-sync.sql).
2. В `src/config.js` укажите URL и публичные ключи своего проекта и нужных API. В репозитории уже настроена конфигурация экземпляра ГульРейтинга.
3. Подключите репозиторий к **Cloudflare Pages** (не Workers):
   - Framework preset: `None`;
   - Build command: оставить пустым;
   - Output directory: `/`.
4. В Supabase откройте **Authentication → URL Configuration**: задайте Site URL вашего домена и добавьте его в Redirect URLs. В **Authentication → Providers → Email** включите Email/Password-вход и выберите, нужно ли подтверждение адреса. Настройте эти параметры под правила доступа вашей компании.

Для локального просмотра можно запустить в корне репозитория:

```bash
python3 -m http.server 8000
```

Затем откройте `http://localhost:8000`. Локальный сервер не исполняет Pages Functions, поэтому прокси Кинопоиска и часть серверных интеграций там могут быть недоступны.

### Ключи и безопасность

`SUPABASE_ANON_KEY` — публичный клиентский ключ; его нельзя считать паролем. Защита данных обеспечивается RLS-политиками в `supabase-schema.sql`. Ключи TMDb и PoiskKino также используются как клиентская конфигурация и могут иметь квоты. **Не добавляйте в `src/config.js` service-role keys, пароли, токен Telegram-бота или другие серверные секреты.** Для Pages Functions секреты задаются в настройках Cloudflare.

У проекта нет отдельного файла лицензии. Публичность исходного кода сама по себе не означает разрешение на его повторное использование.

## Разработка

- Исходники: ванильные JavaScript ES-модули, HTML и статический Tailwind CSS.
- CSS пересобирается командой `./scripts/build-css.sh` после изменения классов.
- Проверки проекта запускаются GitHub Actions для pull request.
- APK собирается workflow **Actions → android-apk**; релиз публикуется при создании тега `v*`.

Подробные изменения по версиям см. в [CHANGELOG.md](CHANGELOG.md). Если нашли ошибку, создайте [issue](https://github.com/ToshakGulina/gulrating/issues/new/choose) с версией приложения, устройством/браузером и шагами воспроизведения. Не прикладывайте пароли, токены или персональные данные.

## Приватность

Данные аккаунтов, профилей, оценок и списков компании хранятся в Supabase. История просмотров и часть настроек сначала сохраняются локально и синхронизируются с личной строкой `user_sync` после установки миграции. Сервис-воркер кэширует файлы оболочки сайта; медиапотоки предоставляются сторонними сайтами и не хранятся в репозитории.
